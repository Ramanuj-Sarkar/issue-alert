Issue Alert · Product requirements

Issue Alert

A personal daily-priority tracker. It stores your issues in a plain-text file and, every day at noon, ranks the 6 it thinks matter most so you stop second-guessing yourself.

status: approved

How the pieces connect

The core journey

Show all steps as a list

    Where ranking comes from

    1. Difficulty — hard first. High outranks Medium outranks Low, so the hard things get finished first.
    2. Deadline within two days — closest first. Any issue due within two days beats one that isn't.
    3. Urgency — high first. The final tie-breaker.

    Drag-to-reorder overrides the automatic order for ties, and your manual placements survive the next noon re-rank. The "why" you read is just the visible values plus the Ranking Explanation you type — the app writes no explanation of its own.

    What you see, screen by screen

    • Labeled rows (one per line): Title, Description, Urgency, Difficulty, Deadline (optional), Ranking Explanation (optional).
    • Urgency and Difficulty picked from Low / Medium / High; Deadline is YYYY-MM-DD or blank.
    • Bad input (wrong date shape, missing Title) shows a visible error and saves nothing.

    • Row order: ignored count (left) · title (large) + truncated description (middle) · urgency, difficulty, deadline (right).
    • Counters count the last two days. Six rows fit on screen; raise the count in code and a down-arrow + scroll reveal the rest.
    • Double-click a row: form-like separate rows, full (untruncated) description and Ranking Explanation, editable; ignored count hidden.
    • X on the left exits back to the list.
    • Completed (blue) or Discarded (red) removes the issue, bumps the matching counter, and the next-ranked issue fills the gap.
    • A fresh list of up to 6 is generated at noon; if fewer exist, only those show, packed to the top.
    • If that happened since you last looked, a red badge appears on the Issues tab and clears when you click it.
    • If the app is open at noon, it alerts in-app. No notification while closed.

    States & boundaries

    StateWhat happens
    First useInput tab shows; Issues tab empty, counters at zero.
    Fewer than 6Only available issues show, packed to the top; empties aren't drawn.
    More than fitsRows stay sized for six; down-arrow + scroll for the rest.
    Invalid inputVisible error; nothing saved.
    No deadlineBlank deadline; no deadline boost in ranking.
    PersistenceIssues, order, explanations, counters survive restart.

    What we're building now

    • Input tab — six fields, validation.
    • Text-file storage — settings in code.
    • Noon ranking — difficulty → deadline → urgency.
    • Issues list — counters, ranked rows, right-side values.
    • Six-fit sizing — scroll + down-arrow when raised.
    • Drag-to-reorder — persists across re-ranks.
    • Detail/edit view — full text, X to exit.
    • Complete / Discard — last-two-day counters.
    • Badge + in-app noon alert.

    Deferred & non-goals

    • A scheduled notification that fires while the app is closed.
    • Optional polish or theming.
    • More levels or a different daily count — enabled by the code settings.
    • Accounts / login / multi-user — a personal tool; no payoff here.
    • Cloud storage or a database — would make the data harder to hand-edit.
    • Mobile app — a local/desktop app shows the loop.
    • Analytics / dashboards / collaboration — resists "add more and more".
    • An app-computed explanation sentence — you chose visible values plus your own note.

    Open question before build: confirm the ranking tier — "deadline within two days" treated as a single tier above everything else. Does not block the technical spec.
