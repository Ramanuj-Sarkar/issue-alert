Issue Alert — App Map

A snapshot of how the finished proof of concept fits together. Source commit 231cbe0.

Issue Alert is a small local app. You add issues, they live in a plain-text file, and the Issues tab shows up to six of them ranked by how long they have been waiting (oldest first), then urgency, then difficulty, then deadline. Each row shows its age in days.

Main pieces

  • server.js — starts Express, serves public/, mounts the API.
  • src/config.js — the settings you change in code: dailyCount, alertTime, the level lists.
  • src/store.js — the only code that reads/writes data/issues.json.
  • src/ranking.js — rank() picks the list; autoCompare sets the order; manual order is layered on.
  • src/scheduler.js — the on-open noon check and the badge logic.
  • src/routes.js — the API the page calls (add, edit, complete, discard, order, seen).
  • public/ — index.html, styles.css, app.js: tabs, form, list, drag, detail, badge, noon timer.
  • data/issues.json — your issues and history, created on first run, hand-editable.

Guided route (walked through in this build)

Follow the action "the list is ordered and each row shows an age":

  1. src/config.js — the two knobs: dailyCount (how many show) and alertTime (when the list is made). Settings only, no logic.
  2. src/ranking.js → autoCompare — the exact function the ranking decision rewrote. Read its four steps in order: age → urgency → difficulty → deadline. rank() caps the result at dailyCount and lays manual placements on top.
  3. public/app.js → daysSinceCreated (used inside renderRow) — turns an issue's createdAt into the number on the left of the row, from the data /api/state returns.

To change this, start here

  • How many issues show, or the noon time → src/config.js (dailyCount, alertTime).
  • The ranking rule → src/ranking.js (autoCompare).
  • What a row shows → public/app.js (renderRow).
  • Colors and type → public/styles.css (:root variables, .issue-row__title).
  • What the API accepts → src/routes.js (validateIssue).
  • How noon and the badge work → src/scheduler.js (ensureGenerated, isBadgeVisible).

A practice to reuse

Decision: rank by age first, and show the age as the row's left number.
Evidence: src/ranking.js → autoCompare implements it; a seeded order test confirmed it, and you could check it by hand-editing one issue's createdAt in data/issues.json and refreshing.
Reuse: when directing an agent, give one observable rule and name where it should live ("the left number is days since creation; sort by it first — this belongs in ranking.js"), then ask for a small verification you can read. A concrete instruction plus a named location plus a checkable result is what made this change fast and safe to confirm.

Run it again

From the project folder: npm install (first time), then npm start, and open http://localhost:3000. Your data is in data/issues.json — change it by hand and reload.
